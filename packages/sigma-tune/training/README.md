# σ-1 QLoRA training

Trains a LoRA adapter on top of **Qwen/Qwen3-30B-A3B** using
[Unsloth](https://github.com/unslothai/unsloth), against the dataset
generated by this package's TypeScript CLI. This directory is plain
Python — it is not part of the pnpm/TS build graph.

## 1. Generate the dataset

From the repo root:

```bash
pnpm --filter @noisebound/sigma-tune generate
```

Writes `training/data/train.jsonl` and `training/data/val.jsonl`.

## 2. Set up the Python environment

Requires a CUDA GPU with enough VRAM for 4-bit QLoRA on a ~30B-total/~3B-active
MoE model (24GB+ recommended). CPU-only training is not supported by this
script.

```bash
python -m venv .venv
source .venv/bin/activate  # .venv\Scripts\activate on Windows
pip install --upgrade pip
pip install "unsloth[cu121-torch240] @ git+https://github.com/unslothai/unsloth.git"
pip install trl datasets pyyaml
```

Pin the Unsloth extras tag (`cu121-torch240` above) to match your installed
CUDA/PyTorch versions — see the
[Unsloth installation instructions](https://github.com/unslothai/unsloth#installation-instructions)
for the current matrix.

## 3. Train

```bash
python training/train.py training/lora_config.yaml
```

Reads every hyperparameter from `lora_config.yaml`. To try a different
learning rate, LoRA rank, batch size, etc., edit that file — `train.py`
itself should not need changes for ordinary tuning runs.

Checkpoints and the final adapter are written under `training/output/`
(gitignored). The final adapter is saved to `training/output/final/`.

## 4. Evaluate

The trained adapter's actual tool-calling behavior should be checked with
`packages/model-eval` against a served checkpoint, the same harness used to
select the base model — this package only produces training data and the
training run, not an eval loop.
